# AZ-104 question style

How getazcertified writes AZ-104 (Azure Administrator) questions. The goal is that a question here *reads like
the real exam*: the same administrator jargon, the same scenario-then-requirement shape, the same kind of
reasoning. The content itself is our own: every scenario is invented, and every correct answer is proven by the
Microsoft Learn page in its `documentation` field. Never write a question from memory of a real exam item.

The general rules and the difficulty profile (AZ-104 is `associate`) are in
[`exam-writing-rules.md`](exam-writing-rules.md). This guide adds what is specific to AZ-104.

Skills measured: the AZ-104 study guide **as of 2026-04-17** (`study_guide: "2026-04-17"`).

## The voice

- Second person, present tense, administrator's point of view: *"You have an Azure subscription that contains…"*,
  *"You need to…"*, *"What should you do?"*.
- Short sentences, one fact per sentence, one paragraph per fact. Name every object (`VM1`, `stfab01`, `RG2`,
  `NSG-Web`) and refer to it by name afterwards.
- US English, like the exam (license, center, minimize).
- Current product names only: Microsoft Entra ID (not Azure AD), Microsoft Entra admin center, Azure Monitor
  Agent, App Service Environment v3, and so on.
- Requirements come as a list after *"The solution must meet the following requirements:"*, or as a single
  qualifier: *"The solution must minimize costs."*, *"…minimize administrative effort."*. A qualifier is load-bearing:
  at least one distractor must work but break it.
- No trick wording, no double negatives. Where a single word decides the answer (*into* a virtual network vs
  *access* a virtual network), it is in plain sight, and the explanation calls it out.

## Archetypes (`archetype` field)

| archetype | shape | lead-in |
|---|---|---|
| `best-choice` | scenario + requirements, one action/resource/setting is right | *What should you use?* / *What should you do first?* / *Which X should you create?* |
| `exhibit-select` | an exhibit (table) of resources, pick the ones that qualify | *Which virtual networks can you connect VM1 to?* |
| `exhibit-statement` | an exhibit, then one statement | *For the following statement, select Yes if the statement is true. Otherwise, select No.* |
| `complete-statement` | an exhibit, then a sentence with a blank | *Select the answer that completes the following statement: "…, ____ will be running."* |
| `complete-code` | a command, template, policy or rule with one blank | *Which value should you use for `<blank>`?* |
| `calculate` | work out a number (instances, VMs available, recovery points) | *What is the maximum number of…?* |
| `goal-solution` | a goal, then one proposed solution | *Solution: … Does this meet the goal?* (Yes/No) |
| `choose-n` | several actions are right | *Which two actions should you perform?* (each correct answer is a complete solution unless the stem says otherwise) |
| `fact-recall` | one fact, little or no scenario | *What is the maximum number of days…?* |

**Series.** The exam often reuses one scenario for several statements. Here, each statement is its own question
file with the same exhibit and an optional `series: "<slug>"` field, so the series stays one scenario while each
file can still be drawn on its own in a practice test.

## Exhibits

The real exam shows tables and configuration panes. Here, an exhibit is a fenced `text` block placed after the
frontmatter, one block per table, aligned by spaces:

````markdown
```text
Name    Location     Address space
VNet1   West Europe  10.10.0.0/16
VNet2   North Europe 10.20.0.0/16
```
````

- The stem says what the block is (*"…the virtual networks shown in the following table."*). The blocks render
  under the stem, in file order.
- Templates, policy rules and commands use the same fence (`text`, or `json` / `bicep` / `powershell` for code).
- Put only what the question needs in the exhibit, plus one or two realistic decoys (a resource that almost
  qualifies).

## Answers and distractors

- 3 to 6 options. Yes/No archetypes have exactly `Yes` and `No`.
- Every distractor is something an administrator might plausibly pick: a real Azure feature that solves a
  *neighbouring* problem, the right feature on the wrong SKU or scope, or a number you'd get by making the classic
  mistake (forgetting the cooldown, dividing without rounding up).
- The site shuffles the answers, so write each option to stand alone: set-style options name every item
  (*VNet1 and VNet2 only*), and never "all of the above" or "none of the above" (the checker refuses those).

## Explanations

Every answer, right or wrong, has a blockquote explanation (`  > …`), which the checker enforces.

- **Correct:** the rule, then how this scenario meets it, in one to three sentences.
- **Wrong:** why this option fails *here* (wrong scope, wrong SKU, solves a different problem), not just "this is
  incorrect".
- Name the trap if there is one (*"Changing the tier doesn't change Last modified."*).

## Truth

- The `documentation` URL must state the fact that decides the answer. Check today's page, not a memory of it.
- Every fact an explanation relies on is on a cited page. When it's on another page, add that page to the
  `documentation` list (up to three), main page first.
  Azure changes: retired SKUs (Basic public IP), renamed products, new limits.
- If the answer depends on a value that changes over time (a limit, a default, a retirement date), say which value
  the question assumes in the explanation.
- Something being retired is still testable while the study guide lists it; mention the replacement in the
  explanation.

## Example (invented)

```markdown
---
question: |-
  You have an Azure subscription named Sub-Retail that is used by several teams.

  You need to ensure that new resources in Sub-Retail can only be created in the West Europe and North Europe regions.

  What should you use?
documentation:
  - title: "Azure Policy overview"
    url: "https://learn.microsoft.com/en-us/azure/governance/policy/overview"
skill_area: "subscriptions-governance"
study_guide: "2026-04-17"
archetype: "best-choice"
---

- [x] An Azure Policy assignment of the Allowed locations definition
  > Allowed locations denies deployments to any region outside the list you set, for every team, at the scope
  > you assign it.
- [ ] A resource lock on Sub-Retail
  > Locks block deleting or changing resources. They can't restrict where new resources are created.
- [ ] A custom Azure role without the write permission for other regions
  > Azure RBAC actions don't include the region, so a role can't limit deployments by location.
```
